# 맥에서 시작하기

현재 파일은 완성된 `.app` 설치 프로그램이 아니라 **소스 코드**입니다. 이전 소스의 Intel iMac Pro / macOS Monterey 12.7.6 웹 앱 빌드는 확인됐습니다. **이번 수정본과 맥 AI 준비 도구의 네이티브 실행 검증은 남아 있습니다.** 빌드 오류가 나오면 멈추고 오류 내용을 확인해야 합니다.

## 1. 파일 받기

이 작업 브랜치의 GitHub 화면에서 초록색 **Code → Download ZIP**을 누릅니다. 다운로드한 ZIP을 더블클릭해 압축을 풉니다. 기본 브랜치 대신 `apps/filmcraft-shorts`가 포함된 작업 브랜치를 내려받아야 합니다.

## 2. 압축을 푼 폴더에서 터미널 열기

1. **⌘ + 스페이스바 → 터미널 → Enter**로 터미널을 엽니다.
2. 터미널에 `cd `를 입력합니다. `cd` 뒤에 공백 한 칸을 넣고, 아직 Enter를 누르지 않습니다.
3. Finder에서 압축을 푼 최상위 폴더를 터미널 창으로 끌어 놓습니다.
4. 폴더 경로가 입력되면 Enter를 누릅니다.
5. `ls Cargo.toml`을 실행했을 때 `Cargo.toml`이 표시되면 올바른 폴더입니다.

## 3. 맥용 실행 파일 만들기

Xcode Command Line Tools와 Rust/Cargo가 설치되어 있어야 합니다. 저장소의 최소 Rust 버전은 1.95입니다. 아래 명령은 소스 코드에서 맥용 프로그램을 만듭니다. 첫 실행에는 의존성을 다운로드하고 빌드하므로 시간이 걸립니다.

```sh
cargo build --locked -p filmcraft-shorts --features whisper -j 4
```

실패하면 뒤의 실행 명령을 입력하지 말고 오류를 확인합니다. 이 코드가 Monterey에서 작동한다고 아직 보장할 수는 없습니다.

## 4. 브라우저 화면 열기

빌드가 성공한 뒤 같은 터미널에서 실행합니다.

```sh
./target/debug/filmcraft-shorts-web
```

터미널을 열어 둔 상태에서 Safari 또는 Chrome의 주소창에 `http://127.0.0.1:8787`을 입력합니다. 이 주소는 **프로그램을 실행한 맥 안에서만** 작동합니다. 서버를 종료하려면 터미널에서 **Control + C**를 누릅니다.

웹에서 촬영본 업로드, 카메라/녹음 역할과 촬영 그룹, 편집 지시를 준비할 수 있습니다. 실제 자동 편집을 시작하려면 아래 AI 준비가 추가로 필요합니다.

## 5. 발언 선택용 로컬 AI 준비

웹 화면만 실행하면 ‘로컬 AI 준비 필요’가 나오는 것이 정상입니다. 발언을 고르는 AI 서버는 별도로 실행해야 합니다. API 키나 외부 AI 계정은 필요하지 않습니다.

웹 서버 터미널은 열어 두고 **⌘ + N으로 새 터미널 창**을 엽니다. 2번처럼 같은 프로젝트 폴더로 이동한 뒤 다음 명령을 실행합니다.

```sh
bash apps/filmcraft-shorts/scripts/setup-mac-ai.sh
```

이 도구는 Homebrew 없이 공식 CMake 3.31.8(고정 SHA-256 확인), llama.cpp b11669(고정 Git 커밋 확인)를 내려받고 CPU용 실행기를 빌드합니다. 이후 Unsloth에서 배포하는 Qwen3-4B-Instruct-2507 Q4_K_M GGUF 모델 약 2.5GB를 다운로드해 해당 배포처 메타데이터의 SHA-256과 크기로 검증합니다. 첫 설치에는 여유 공간 약 6GB 이상과 인터넷 연결이 필요합니다. 영상·대본은 업로드하지 않습니다. 기존 사용자 파일은 덮어쓰지 않고, 충돌하면 오류로 중단합니다.

다운로드·빌드가 끝나면 같은 창에서 실행하세요.

```sh
bash apps/filmcraft-shorts/scripts/start-local-model.sh
```

모델 로딩이 끝날 때까지 기다리세요. 이 창도 켜 두고 브라우저의 **실행 환경 → 준비 상태 다시 확인**을 누릅니다. `interview-local` 모델이 실제로 서비스되는지 확인한 뒤 편집 버튼이 활성화됩니다. CPU로 실행하므로 긴 대본 처리는 느릴 수 있습니다. 다음 사용부터는 준비 스크립트 없이 시작 명령만 실행하면 됩니다.

설치 위치는 `~/Library/Application Support/FilmcraftShorts/ai`입니다. `FILMCRAFT_AI_DIR`를 설정하면 준비·시작 명령 양쪽에 같은 경로를 사용하세요. 음성 인식용 Whisper 가중치는 첫 편집 때 별도로 내려받습니다. 다운로드 실패·TLS 오류·빌드 오류는 마지막 오류 내용을 확인하고 진행을 멈추세요. 인증서 검증을 끄지 마세요.

**검증 범위:** 이 맥 준비 도구는 Linux에서 구문과 경로·다운로드 검증 로직을 검사했습니다. Intel Monterey에서 CMake/llama.cpp 네이티브 빌드를 실행하거나 실제 한국어 인터뷰 품질을 확인한 것은 아닙니다. 웹 앱의 네이티브 빌드는 사용자 맥에서 성공한 상태입니다.

## 6. 소탐대실 자막 스타일

**편집 방향 → 자막 디자인 → 소탐대실**을 선택합니다. 촬영본 목록의 **자막 화자**에서 각 오디오 소스가 게스트인지 제작진인지 지정합니다. 선택된 마이크에 따라 게스트는 노랑, 제작진은 청록, 제목은 청록으로 출력됩니다. 하나의 녹음에 두 화자가 섞여 있으면 그 파일의 지정이 적용되며, 목소리만으로 역할을 검증하지는 않습니다.

기본 프리셋 외에 **편집 방향 → 자막 PSD 불러오기**로 PSD의 텍스트 스타일을 가져올 수 있습니다. 제목은 전체 영상 동안 상단에 유지되고 긴 제목은 두 줄로 나눕니다. 말자막은 원문 단어를 사용하고 컷마다 화자 스타일을 분리합니다. 편집 프로젝트에는 세 개의 표시 트랙과, SRT 내보내기용 통합 대사 트랙(표시 꺼짐)이 있습니다. SRT는 대사·시간만 포함하며 색상·글꼴은 MP4와 편집 프로젝트에 반영됩니다.

PSD의 `SDCheongRyu`, `GangwonEduAll-OTFBold` 글꼴은 프로그램에 포함하지 않았습니다. 산돌구름에서 활성화하거나 사용 권한이 있는 글꼴을 설치한 뒤, 아래 **산돌구름 활성 글꼴 사용** 안내에 따라 선택하세요. 선택한 글꼴을 읽지 못하거나 자막의 글자를 표시하지 못하면 오류로 중단합니다. 원본 PSD의 자간과 정확한 글리프 위치까지 동일한 재현은 아니므로 짧은 결과로 확인하세요.

## 산돌구름 활성 글꼴 사용

최신 프로그램으로 업데이트하고 한 번 다시 빌드·실행한 뒤 사용하세요.

1. Mac의 산돌구름 앱에서 사용할 글꼴을 활성화합니다.
2. 편집 방향 화면에서 **글꼴 목록 새로고침**을 누릅니다.
3. 제목·말자막 입력란에서 실제 글꼴 이름을 선택합니다. PSD의 PostScript 이름과 표시 이름이 다를 수 있습니다.
4. **한국어 출력 검사**를 눌러 선택한 글꼴로 예문을 실제 렌더링할 수 있는지 확인합니다.
5. 편집을 시작합니다. 출력 시 활성 상태와 실제 자막의 글자 지원을 다시 확인합니다.

활성화·해제 후에는 서버 재시작 없이 목록을 새로고침하면 됩니다. 검사 이후에도 편집 완료까지 글꼴을 활성화해 두세요.
산돌구름 계정이나 파일 업로드 없이 macOS가 등록한 읽기 가능한 글꼴만 조회합니다. 보호된 글꼴, 앱 전용 글꼴, 지원하지 않는 형식은 제외될 수 있습니다. 비활성 글꼴이나 표시할 수 없는 글자가 있으면 안내하고 출력을 중단합니다.

이 연결은 공식 산돌구름 API 연동이 아닙니다. 클라우드의 Linux 테스트와 Mac 대상 컴파일 검사는 가능하지만, 실제 산돌구름 구독 글꼴의 사용 가능 여부는 해당 Mac에서 위 출력 검사로 확인해야 합니다. 글꼴 사용 범위는 해당 구독·글꼴의 이용 조건을 따릅니다.

## PSD 자막과 꽉 찬 세로 화면

1. 이전 웹 서버를 종료하고 최신 소스로 다시 빌드·실행합니다. 이미 준비한 AI 모델은 다시 설치하지 않습니다.
2. 자막 없는 원본 촬영 영상과 마이크 녹음을 올리고, 같은 촬영 파일을 같은 그룹에 넣습니다.
3. **편집 방향 → 자막 PSD 불러오기**에서 PSD를 선택합니다. 전달된 소탐대실 PSD의 제목·제작진·게스트 텍스트 레이어 읽기를 검증했습니다.
4. **글꼴 목록 새로고침** 후 제목·게스트·제작진 글꼴을 확인하고 **한국어 출력 검사**를 실행합니다. PSD는 글꼴 파일을 포함하지 않으므로 산돌구름 활성화가 필요합니다.
5. 편집을 시작하면 중앙 기준으로 영상을 확대·크롭해 1080×1920 화면을 채웁니다. 좌우 가장자리는 잘릴 수 있으며, 사람 얼굴을 추적하는 자동 리프레임은 아직 아닙니다.

말자막은 선택된 오디오의 원문과 인식된 단어 시간을 사용합니다. 약 16자·2초 단위로 나누고 문장 끝·화자 변경·쉼에서 구분합니다. 긴 단일 인식 구간을 나눌 때는 해당 구간 안에서 시간을 비례 배분하므로 실제 음절 시점과 차이가 날 수 있습니다. SRT와 영상은 같은 말자막·시간을 사용합니다. 한국어를 지원하지 않는 글꼴은 기본 모드에서도 오류로 중단해 `NO GLYPH` 출력물을 만들지 않습니다.

PSD 지원 범위: PSD v1, 9:16 캔버스, 편집 가능한 텍스트 레이어 세 개(상단 제목, 이름에 게스트/guest·제작진/crew가 있는 말자막). 글꼴 이름, 단색 글자색, 변환이 적용된 크기, 세로 위치, 줄 간격, 단색 테두리를 읽습니다. 최대 128MB. PSD 이미지·문구 자체를 영상에 덧씌우거나 글꼴을 추출하지 않습니다. 자간·복합 효과·회전·왜곡·혼합 서식·픽셀 단위 일치는 지원하지 않습니다. 결과물이 이미 자막과 오류 글자를 포함하면 제거할 수 없으므로 원본 촬영본으로 다시 편집하세요.

## 발언 선택에서 약 30분 후 멈춘 경우

이전 버전에는 AI 요청 전체를 30분 후 종료하는 제한이 있었습니다. 새 버전은 단어·촬영본을 빼지 않고 AI 입력을 압축하며, 기본 대기 한도를 2시간으로 늘렸습니다. 이 한도는 속도 보장이나 완료 예정 시간이 아닙니다. CPU 처리 시간은 대본 길이와 컴퓨터 성능에 따라 달라집니다. M17.6부터 긴 대본은 자동으로 작은 분량으로 나누어 검토합니다. 아래 안내를 참고하세요.

1. 웹 서버(8787) 터미널에서 Control+C를 누르고 최신 소스로 다시 빌드·실행합니다. 정상 작동하는 AI 서버(8000)는 그대로 두세요. 모델을 다시 다운로드하지 않습니다.
2. 브라우저에서 **작업 기록 → 실패한 작업의 상태 확인 → 분석 재사용하고 다시 시도**를 누릅니다.
3. 완료된 동기화·인식 대본을 불러와 발언 선택부터 시작합니다. 이전 실패 기록과 파일은 보존되고 새 작업 기록이 생깁니다.

재시도 버튼이 없으면 완료된 분석 파일이 없는 작업입니다. 원본·작업 설정이 달라지거나 저장된 대본과 프로젝트가 일치하지 않으면 재사용을 거절합니다. 원본 파일의 크기와 엔진의 앞·뒤 부분 지문으로 변경 여부를 확인하며 전체 파일의 암호학적 검증은 아닙니다. 이전 버전의 분석도 원래 작업 기록과 파일이 남아 있으면 재사용할 수 있습니다.

시간 초과·HTTP 거절·연결 끊김은 별도 문구로 표시합니다. `/health`의 `ok`는 서버가 살아 있다는 뜻으로, 긴 대본의 처리 속도나 문맥 길이까지 보장하지 않습니다. 개발·자동 테스트는 확인했지만 실제 사용자 Mac에서 긴 한국어 대본의 완료 시간과 선택 품질을 검증한 것은 아닙니다.

고급 설정: 웹 서버를 시작하기 전에 `FILMCRAFT_PLANNER_TIMEOUT_SECONDS`를 60~21600초 사이로 설정할 수 있습니다. 기본은 7200초이며 실행 중인 웹 서버에는 자동 반영되지 않습니다.


## HTTP 400: 대본이 32K 한도를 넘는 경우 (M17.6)

AI 터미널에 `request (140764 tokens) exceeds the available context size (32768 tokens)`처럼 나오면 AI가 고장난 것이 아니라 프로그램이 대본을 너무 많이 보낸 것입니다. M17.6은 대본을 작은 구간으로 나눠 후보를 고른 뒤, 원문 후보를 비교해서 제목과 최종 구성을 정합니다. AI 모델을 다시 받거나 AI 설정을 바꿀 필요는 없습니다.

1. 최신 ZIP을 새 폴더에 풀고, 실행 중인 **8787 웹 서버만** Control+C로 종료합니다. 8000 AI 창은 그대로 둡니다.
2. 새 폴더에서 `cargo build --locked -p filmcraft-shorts --features whisper -j 4`를 실행합니다.
3. Finished 뒤 `./target/debug/filmcraft-shorts-web`을 실행합니다.
4. 브라우저에서 `http://127.0.0.1:8787`을 열고 ⌘+Shift+R로 새로고침합니다.
5. 작업 기록에서 앞서 AI 요청이 실패한 작업의 상태 확인 → **분석 재사용하고 다시 시도**를 누릅니다.
