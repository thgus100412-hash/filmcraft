# FilmCraft Shorts

한국어 인터뷰의 여러 촬영본과 별도 녹음을 받아, 자연어 주제·뉘앙스에 맞는 발언을 고르고 제목과 자막이 있는 세로 영상을 만드는 헤드리스 프로그램입니다. FilmCraft의 실제 import / waveform sync / Whisper / timeline / captions / export 명령을 사용합니다. 원본 미디어는 수정하지 않습니다.

**맥 사용자:** 먼저 [맥에서 시작하기](MAC-START-HERE.md)를 읽어 주세요. 아래 `/workspace` 기반 스크립트는 Linux 클라우드용이며 맥에서 그대로 실행하지 않습니다.

## 소탐대실 자막과 맥 AI 준비

[맥 안내](MAC-START-HERE.md)의 5–6번에 AI 준비·시작과 자막 사용법이 있습니다. 브라우저의 소탐대실 프리셋은 제목·제작진·게스트 세 표시 트랙과 통합 SRT 트랙을 만듭니다. 마이크별 `caption_role`은 `guest`(기본) 또는 `crew`이며, 역할을 검증하는 얼굴/성문 인식은 아닙니다. `caption_design`은 `standard`(기존 JSON의 기본) 또는 `sotam`(웹 기본), `title_font`와 `dialogue_font`로 설치 글꼴 이름을 지정합니다. 원본 PSD·폰트는 배포하지 않으며 9:16 PSD의 제목·제작진·게스트 텍스트 스타일 업로드를 지원합니다(지원 범위는 맥 안내 참조). Mac에서는 산돌구름으로 활성화한 글꼴을 새로고침해 선택하고 한국어 출력 검사를 할 수 있습니다. 보호되거나 앱에서 읽을 수 없는 글꼴은 제외됩니다. 자간과 글리프 위치의 픽셀 단위 일치는 보장하지 않습니다.

## 웹 화면으로 사용하기

JSON 파일을 직접 편집하지 않고 브라우저에서 촬영본과 녹음을 추가할 수 있습니다.

```sh
cd /workspace/filmcraft
bash apps/filmcraft-shorts/scripts/start-web.sh
```

실행한 컴퓨터의 브라우저에서 `http://127.0.0.1:8787`을 엽니다. 이 서버는 로컬 전용이며 공개 사이트로 배포하지 않습니다. 클라우드의 루프백 주소는 사용자 PC의 루프백 주소와 다르므로 이 주소를 외부 접속 링크로 사용하지 마세요.

1. **촬영본 준비:** 파일을 드래그하거나 선택하고, 카메라/별도 녹음 역할과 촬영 그룹을 지정합니다. 설명에는 “게스트 클로즈업”, “진행자 핀 마이크”처럼 알고 있는 정보를 넣습니다.
2. **편집 방향:** 주제·뉘앙스, 최대 길이, 인식 정밀도를 선택합니다.
3. **자동 편집:** 실제 처리 단계와 오류를 확인하고 필요하면 취소합니다. 서버가 켜져 있으면 브라우저 새로고침 후에도 작업을 다시 확인할 수 있습니다.
4. **결과 확인:** 영상 미리보기, MP4·SRT·편집 프로젝트·편집 계획 다운로드와 발언 선택 이유를 확인합니다.

**실행 환경** 화면에서 로컬 AI와 음성 모델 준비 상태를 확인할 수 있습니다. 웹 화면은 모델 없이도 열리지만, 로컬 편집 AI가 준비되지 않으면 편집 시작 버튼이 비활성화됩니다. 아래 로컬 모델 준비 안내를 따라 모델을 내려받고 별도 터미널에서 `start-local-model.sh`를 실행해 두어야 합니다. 실제 한국어 ASR/발언 선택 품질은 아직 모델과 인터뷰로 검증하지 않았습니다.

업로드와 결과는 `/workspace/.filmcraft-shorts-web`에 보관합니다. 파일당 8GB, 업로드 전체 20GB, 동시 편집 1개를 지원합니다. 파일 목록의 ×로 아직 작업에 쓰지 않은 업로드 사본을 지울 수 있습니다. 작업에 사용한 사본은 프로젝트가 다시 열릴 수 있도록 보존합니다. 브라우저의 초안에는 파일 정보와 편집 지시만 저장하며, 원본 파일을 변경하지 않습니다. 서버를 종료하면 진행 중인 편집도 중단되며, 완료된 기록과 결과는 보관합니다. 강제 종료 후에는 중단 상태로 표시하고 자동 재개하지 않습니다.

일반 로컬 개발에서는 `cargo build -p filmcraft-shorts --features whisper` 후 `target/debug/filmcraft-shorts-web`을 실행할 수도 있습니다. `--port`, `--data-dir`로 포트와 저장 폴더를 지정합니다. 브라우저 화면은 HTML/CSS/JavaScript로 실행 파일에 포함되어 별도 Node 서버가 필요 없습니다.

### 웹 검증

`cargo test -p filmcraft-shorts --features whisper`에 HTTP 통합 테스트가 포함됩니다. 업로드, 입력 검증, 중복 실행 방지, 작업 취소, 기록, 결과 다운로드와 영상 바이트 범위, 외부 Origin/Host 거부, 미사용 업로드 삭제 및 기존 프로젝트 파일 보존을 검사합니다. 이 테스트의 작업 프로세스는 모의 프로세스이며, 실제 동기화/인코딩은 별도 `pipeline.rs`가 검사합니다.

Playwright와 Chromium이 있는 개발 환경에서는 웹 서버를 켠 뒤 아래 명령으로 업로드·그룹·초안 복원·준비 상태·기록/결과 화면·모바일 레이아웃을 검사할 수 있습니다. 준비 상태와 완성 작업 기록은 UI 검증용 모의 응답이며, 한국어 모델 품질을 검사하지는 않습니다. 스크린샷은 `/tmp/filmcraft-shorts-web-*.png`에 생성합니다.

```sh
node apps/filmcraft-shorts/tests/browser.cjs
```

## CLI 실행

Rust 1.95 이상, C/C++ 빌드 도구, 한국어 글꼴(Noto Sans CJK KR 권장)이 필요합니다. 실제 음성 인식은 Whisper 모델 다운로드가 필요하며 CPU에서 실행합니다. 기존 단어별 대본 JSON을 각 source의 `transcript` 경로로 제공하면 인식과 모델 다운로드를 생략합니다.

```sh
cargo build -p filmcraft-shorts --features whisper
cp apps/filmcraft-shorts/job.example.json /path/to/job.json
# job.json의 파일 경로, 카메라 구도/마이크 라벨, 주제, 모델 설정을 실제 값으로 수정
# 인증이 필요한 경우 FILMCRAFT_PLANNER_KEY는 환경 설정에서 안전하게 주입
./target/debug/filmcraft-shorts /path/to/job.json /path/to/new-result --render
```

`job.json` 내부 경로는 그 JSON 파일의 디렉터리 기준입니다. 출력 디렉터리는 새 경로여야 합니다. `--render` 없이 실행하면 편집 프로젝트와 자막까지 만듭니다. `--plan plan.json`은 저장한 편집 계획을 재실행/테스트하는 선택 옵션이며, 일반 사용에서는 수동 발언 구간이나 계획 입력이 필요하지 않습니다.

`planner.url`은 OpenAI 호환 `/v1/chat/completions` 엔드포인트입니다. 로컬 한국어 모델 서버의 localhost/127.0.0.1 주소와 포트만 허용합니다. 외부 서버 주소는 거부합니다. 설정한 로컬 서버로 **전체 인식 대본, 화자 라벨, 시간 정보, 주제와 촬영 그룹 이름**이 전송됩니다. 원본 영상/오디오 파일과 파일 경로는 보내지 않습니다. 외부 유료 API는 호출하지 않습니다. 모델이 JSON 응답 형식을 지원해야 하며 전체 대본이 모델 컨텍스트에 들어가야 합니다. 자동으로 유료 서비스를 선택하거나 호출하지 않습니다.

## 로컬 편집 모델 서버

클라우드 환경에는 공식 llama.cpp b11669 CPU 실행기를 SHA-256 검증 후 `/workspace/.local-model/llama-b11669/`에 설치했습니다. 제품에 링크하거나 배포하지 않는 별도 로컬 추론 서비스입니다. 모델 가중치는 별도로 필요합니다. 기본 대상은 한국어를 지원하는 Qwen3-4B-Instruct-2507 Q4_K_M이며, 실제 인터뷰 편집 품질은 아직 검증하지 않았습니다.

```sh
# 모델 다운로드 도메인이 환경 설정에서 허용된 뒤 실행
python3 apps/filmcraft-shorts/scripts/fetch-local-model.py
bash apps/filmcraft-shorts/scripts/start-local-model.sh
# 다른 터미널에서 준비 상태 검사
curl --fail http://127.0.0.1:8000/health
```

다운로드 도우미는 Unsloth 배포 저장소 메타데이터의 리비전, 파일 크기, SHA-256으로 가중치를 검증하고 영수증을 남깁니다. 모델이 없으면 시작 스크립트는 명확한 오류로 중단합니다. 기본 서버는 CPU 4스레드, 32K 컨텍스트이며 대본이 너무 길면 작업을 촬영 그룹별로 나눠야 합니다. 컨텍스트를 넘는 대본의 자동 계층 요약은 아직 없습니다. 모델 서비스 프로세스는 환경 재시작 후 다시 실행해야 합니다.

## 촬영 그룹과 오디오

동시에 촬영한 카메라와 녹음은 같은 `groups` 항목으로 묶습니다. 서로 다른 테이크/세션은 별도 그룹으로 둡니다. 각 그룹의 첫 번째 카메라를 기준으로 파형을 맞추며, 공유 타임코드가 있으면 `sync: "timecode"`도 사용할 수 있습니다. 파형 동기화에는 공통 소리가 필요합니다. 녹음이 겹치지 않거나 무음이면 오류로 중단합니다. 기존 동기화 엔진의 분석 범위는 각 파일 시작부터 최대 30분이며, 장시간 녹음의 시계 드리프트 보정은 아직 없습니다.

편집 모델은 그룹별 모든 대본과 단어 시간을 받아 발언, 카메라, 마이크를 구간마다 선택합니다. 출력 타임라인에는 선택한 카메라의 영상과 선택한 마이크의 오디오만 배치하므로 다른 마이크와 카메라의 스크래치 오디오가 중복 재생되지 않습니다. 발언에 따라 마이크를 바꾸려면 계획이 화자 전환 지점에서 분할되어야 합니다.

마이크/구도 `label`은 알려진 정보를 설명하는 선택 입력입니다. 현재 화자와 마이크의 대응은 **대본과 라벨에 기반한 모델 판단**입니다. 얼굴·입 모양 인식, 목소리 지문으로 인물 매칭, 누음 제거, 겹쳐 말하는 두 사람의 동시 믹싱, 음질 기반 마이크 선별은 아직 구현하지 않았습니다. 외부 마이크 라벨이 없거나 여러 녹음에 같은 대화가 섞이면 선택이 부정확할 수 있습니다. Whisper 화자 번호는 파일 사이에서 동일 인물을 뜻하지 않습니다.

## 처리와 산출물

1. 촬영 그룹별 미디어를 가져와 멀티캠 동기화하고, 파형 신뢰도를 검사합니다.
2. 한국어 단어별 대본과 화자 정보를 추출합니다. 없으면 체크섬 검증을 유지한 채 모델을 다운로드합니다.
3. 자연어 지시로 편집 모델에 원문 단어 구간 선택·제목 작성을 요청합니다.
4. 모델이 반환한 그룹/소스/단어 번호, 카메라 구간 커버리지, 중복 발언, 최대 길이를 검증합니다. 임의의 시간코드나 재작성한 인용문은 받지 않습니다.
5. 1080×1920, 30fps 시퀀스에 선택 구간을 연결하고 원문 자막과 상단 제목을 만듭니다. 영상은 화면 안에 맞춰 배치하므로 가로 영상에 여백이 생길 수 있습니다.
6. 선택적으로 FilmCraft 인코더로 자막이 입혀진 H.264 MP4를 출력합니다.

- `sources.fcproj`: 동기화된 소스/대본 프로젝트 (모델 요청 전에 저장)
- `analysis.json`: 편집 모델 입력과 동기화 결과
- `plan.json`: 선택 구간·카메라·마이크·선택 이유·제목
- `short.fcproj`: 데스크톱 FilmCraft에서 열어 수정할 수 있는 결과
- `captions.srt`: 본문 자막
- `short.mp4`: `--render`를 지정했을 때 출력

완성도 검수는 필요합니다. 의미 보존은 모델 프롬프트로 요구하지만 코드만으로 증명할 수 없습니다. 영상 내용 분석이나 인물 추적 자동 리프레임은 없으며, 현재 카메라 판단은 대본·구도 라벨·실제 구간 존재 여부를 사용합니다. CLI와 로컬 웹 화면을 제공하며, 공개 호스팅이나 사용자 계정 기능은 포함하지 않습니다.

## 검증

```sh
cargo test -p filmcraft-shorts
cargo clippy -p filmcraft-shorts --all-targets -- -D warnings
```

단위 테스트는 별도 마이크와 카메라의 시간 변환, 잘못된 계획 거부, 별도 테이크, 실제 엔진의 자막/오디오 조립을 검증합니다. 통합 테스트는 FFmpeg를 **합성 테스트 미디어 생성/출력 검사에만** 사용하며, 시간차가 있는 두 카메라와 WAV를 실제 엔진으로 동기화하고 작은 해상도의 자막 MP4를 출력합니다. 이 테스트의 대본과 편집 계획은 고정 데이터이므로 실제 한국어 인식률이나 LLM 편집 품질을 검증하지는 않습니다.

### 현재 환경에서 확인한 결과 (2026-10-20)

Rust 1.95.0에서 Whisper 포함 빌드, Shorts 테스트 7개, speech 라이브러리 테스트 16개, Clippy, 의존 계층 검사와 자산 출처 검사를 수행했습니다. 합성 촬영본 2개·별도 WAV 2개를 동기화하고 구간별 마이크를 전환했으며, CLI에서 오디오가 있는 1080×1920 MP4(약 1초), 프로젝트와 SRT를 출력했습니다. 한국어 제목·본문 자막을 렌더링한 프레임을 눈으로 확인했고, 자막을 숨긴 출력과 픽셀이 달라지는 것도 검사했습니다.

로컬 llama.cpp 실행기는 설치하고 버전/실행 옵션을 확인했습니다. 실제 Whisper/Qwen 가중치 다운로드는 Hugging Face 접근에 대한 프록시 403으로 아직 막혀 있습니다. 필요한 네트워크 도메인과 설치·시작 지침은 환경 설정 초안에 저장했으며, 적용·게시 및 모델 기반 추론은 완료하지 않았습니다. 실제 인터뷰의 한국어 인식률, 주제·뉘앙스 선택 품질과 화자별 마이크 선택 정확도는 가중치 준비 후 별도 검증해야 합니다.

### PSD·세로 화면·말자막 수정

웹에서 PSD를 올리면 제목·게스트·제작진 텍스트 레이어의 지원 스타일을 `caption_template` JSON으로 작업에 저장합니다. 역할별 글꼴은 각각 선택할 수 있으며 `crew_font` 생략 시 기존 말자막 글꼴을 사용합니다. PSD 파일과 글꼴은 결과에 재배포하지 않습니다. 기본 모드에도 글리프 지원 검사를 적용하고 실제로 검사한 글꼴을 렌더러에 넘깁니다. 영상은 `clip.fillFrame`으로 중앙 크롭하며 얼굴 추적 기능은 포함하지 않습니다. 말자막과 SRT는 동일한 단어 시간 기반 큐를 공유합니다. 긴 ASR 단위의 분할 시각은 비례 추정입니다.

검증에는 합성 촬영본·마이크, 잘린 PSD/잘못된 입력, 9:16 출력 모서리 픽셀, 기본 모드 글꼴 적용, 한국어 글리프 누락 차단을 사용합니다. `FILMCRAFT_TEST_PSD`를 개인 PSD 경로로 지정하면 해당 파일의 스타일 읽기와 HTTP 업로드를 추가 검사하고, 시스템에 Noto Sans CJK KR이 있으면 오픈 글꼴로 한국어 렌더링을 확인합니다. 개인 PSD와 산돌구름 글꼴은 저장소에 넣지 않으며 실제 산돌구름 렌더링은 사용자 Mac에서 확인해야 합니다.
